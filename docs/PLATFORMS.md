# Платформы и управление

Один Flutter-проект для macOS, Windows, iOS и Android. Версия SDK закреплена
в .fvmrc: 3.47.4. Это выше минимума 3.47.1, необходимого для автономных
Windows-сборок Flutter GPU. Движок включён в Info.plist iOS/macOS,
application meta-data Android и DartProject Windows runner.

## Запуск в IDE

Выбрать «Crime Oren · macOS» в списке Run/Debug. Все конфигурации в
.vscode/launch.json явно используют lib/main.dart: активный файл теста
или tools/qa/inspect_game.dart не меняет точку запуска игры. Для Windows
есть отдельная конфигурация, для iOS/Android — выбор устройства.

```sh
fvm flutter run -d macos --enable-flutter-gpu
# На Windows:
fvm flutter run -d windows --enable-flutter-gpu
# Сборка Android без установки на телефон:
fvm flutter build apk --debug
```

## Desktop

- WASD / стрелки — ходьба, газ/тормоз и руль в машине;
- Shift — бег;
- Space — прыжок пешком, ручник за рулём;
- E — сесть / выйти / угнать ближайшую машину;
- Клик по сцене — захват курсора; мышь / тачпад — поворот камеры;
- ПКМ — прицеливание;
- ЛКМ или F — огонь; R — перезарядка;
- B — передохнуть у лавочки; H — купить дом / сохранить в своём доме;
- M — звук, по умолчанию выключен;
- Esc — пауза / продолжение.

Используются физические позиции WASD и буквенных действий, поэтому
русская раскладка не мешает. На ПК нет виртуального стика, педалей и
кнопок прыжка/огня. Подсказка управления и доступные взаимодействия
остаются в HUD. На macOS используется нативный относительный ввод: курсор скрывается
после клика по сцене, а его положение не ограничивает поворот камеры.
Esc и потеря фокуса освобождают курсор. Для остальных desktop-runner
пока предусмотрен fallback по движениям указателя, без нативного raw-input.

Потеря фокуса сбрасывает удерживаемые действия и ставит desktop-игру
на паузу. Пауза пропускает игровой tick и передаёт компонентам сцены
нулевой dt; при возвращении нет накопленного wall-clock шага. Окно
изменяет размер, минимум 960×600, первоначально до 1280×800.
Сенсорное управление и ориентации на iOS/Android сохраняются.

## Проверки

```sh
fvm flutter test
fvm flutter analyze
fvm dart --packages=.dart_tool/package_config.json tools/qa/inspect_game.dart <VM URL> --desktop-smoke
fvm dart --packages=.dart_tool/package_config.json tools/qa/inspect_game.dart <VM URL> --smoke
```

Desktop smoke проверяет заморозку часов и компонентов, движение после
паузы, прицел без расхода патронов. Стартовать пешком. Не управлять игрой
во время сценария. Клавиатура/мышь отдельно покрыты widget-тестами, в том
числе потеря фокуса и независимое удержание F/ЛКМ.

macOS: собрана и запущена нативная debug-сборка. Android: универсальный
debug APK собран; на Android-устройстве этот этап не проверялся. Windows:
настроен runner и ручной workflow .github/workflows/windows.yml; удалённый
workflow не запускался, нативная Windows-сборка ещё не подтверждена.
Это не опубликованные релизные сборки для магазинов.

## Исправление macOS Metal

Metal validation установил причину нативного сбоя: попытка привязать
текстуру к индексу 4294967295. Пользовательский ground.fmat с shading_model
shadowCatcher читал только солнечные тени, и компилятор удалял неиспользуемые
punctual-сэмплеры, которые движок продолжал привязывать. Шейдер теперь
соблюдает полный контракт shadow-catcher, включая условные тени
прожекторов. Качество/тени не отключались. Исправление проверено с Metal
API Validation, затем выполнен обычный запуск без диагностической среды.
Заимствованная функция и MIT-уведомление указаны в assets/models/CREDITS.md.

В этой сессии 245 тестов прошли; анализатор без ошибок/предупреждений,
три прежних info. Общий smoke на macOS прошёл целиком: камера, ходьба/бег,
посадка, разгон/торможение, столкновение с деревом, рельеф и четыре колеса,
поворот на скорости, ручник и угол кузова возле стены. `--desktop-smoke`
подтвердил остановку времени/компонентов на паузе, возобновление движения
без скачка и прицеливание без выстрела. В `--city-smoke` и `--areas-smoke`
на desktop снимается только состояние через VM; снимки симулятора
автоматически пропускаются, поэтому iPhone не требуется для этих проверок.

Настройки Flutter GPU сверены с документацией используемого движка:
https://github.com/bdero/flutter_scene#enable-flutter-gpu .

После пересоздания устаревших hook.dill iOS-сборка для симулятора успешно
собрана (`build/ios/iphonesimulator/Runner.app`). Новый runtime-прогон iOS
на этом этапе не выполнялся; основной игровой прогон выполнен на macOS.


Исправлена чрезмерная резкость после перехода на native pointer: desktop
теперь передаёт контроллеру реальный viewportSize, как мобильный
CameraControls. Ввод нормируется по высоте окна, чувствительность 0.75,
события объединяются по кадрам и сглаживаются с постоянной 20 мс. При
освобождении курсора очередь движения очищается. Проверены сохранение
угла на 60/120 Гц и отсутствие остаточного движения после release.
