# Проверка Crime Oren

## Запуск

```sh
fvm flutter devices
fvm flutter run --enable-flutter-gpu -d <simulator-uuid>
```

В этой сессии использовался iPhone 18 Pro Max, iOS 27.0:
`BBA66C99-1756-4D0B-8E7B-2E797F9284F0`.

## Проверки без GPU

```sh
fvm flutter test
fvm flutter analyze
```

Тесты камеры используют аналитические препятствия: свободное пространство,
стена, край проёма вне центрального луча, препятствие вплотную к точке
взгляда. Тесты движения проверяют аналоговую скорость и ограничение
диагонали. Тесты транспорта — ограничение руления на скорости и полный
выворот на парковке. Эти проверки не заменяют проверку реальной сцены.

## Сценарий на работающей 3D-сцене

Скопировать HTTP-адрес Dart VM Service из вывода `flutter run`:

```sh
fvm dart --packages=.dart_tool/package_config.json tools/qa/inspect_game.dart <vm-service-url> --smoke
```

Сценарий проверяет четверть и полный ход стика, бег, втягивание камеры
у дома на Весенней и восстановление после разворота, посадку с перестройкой
HUD, разгон, торможение и высадку. Перемещения проходят через игровые
компоненты, а не через поддельные снимки состояния. Во время сценария
не управлять персонажем вручную. Сценарий возвращает позиции и сбрасывает
свой ввод в `finally`; сохранение на диск не вызывает. Трафик, NPC и время
продолжают работать, поэтому весь мир к исходному состоянию не откатывается.

Инструмент подключается только к debug VM Service; игровых команд или
тестового меню в release-сборку он не добавляет. Обычное выражение вместо
`--smoke` вычисляется в контексте Game. Флаг `--app` выбирает библиотеку
main.dart, например для проверки ориентации:

```sh
fvm dart --packages=.dart_tool/package_config.json tools/qa/inspect_game.dart <vm-service-url> 'SystemChrome.setPreferredOrientations([DeviceOrientation.landscapeLeft])' --app
```

После проверки вернуть разрешённые ориентации горячим перезапуском `R`.
Скриншоты получать через `xcrun simctl io <uuid> screenshot /tmp/crime-oren.png`.
Проверять обе ориентации, пеший и автомобильный HUD, отсутствие перекрытий
контролов и отладочной панели. Диагностика открывается кнопкой ползунков;
в release кнопки и панели нет.

## Ограничения

- FPS debug-сборки в симуляторе не означает FPS реального iPhone.
- Проверка через VM Service проверяет игровые системы и перестройку HUD,
  но не подтверждает удобство управления пальцами или распознавание жестов.
- Камера сейчас сталкивается с геометрией чанков (здания, земля, дороги).
  Люди, декоративные деревья и автомобили не входят в её коллизионную область.
- Машины остаются кинематическими: полноценной подвески и rigid-body
  столкновений этот проход не добавляет.

## Окружение

Инструмент поддерживает контексты `--trees`, `--facades` и `--fps`:

```sh
fvm dart --packages=.dart_tool/package_config.json tools/qa/inspect_game.dart <vm-service-url> '"trees=$treeCount trunks=${trunks.instanceCount} crowns=${canopies.instanceCount}"' --trees
fvm dart --packages=.dart_tool/package_config.json tools/qa/inspect_game.dart <vm-service-url> '"facades=${_ready.length} failed=$_failed"' --facades
fvm dart --packages=.dart_tool/package_config.json tools/qa/inspect_game.dart <vm-service-url> '"ui=$_uiMs raster=$_rasterMs"' --fps
```

При проверке окружения 12.11.2026 прошли 179 тестов; осмотрены жилой фасад
днём и ночью, новые деревья и снежный покров 0.85. Посадка оставляет место
под крону радиусом 3.1 м, а число стволов/крон совпадает после удаления и
повторного добавления дерева. На снимках оценивать также края листвы,
масштаб относительно человека, отсутствие деревьев в домах/дорогах и
чрезмерной яркости окон. Стволы останавливают персонажа и управляемый автомобиль через
аналитические цилиндры; листва остаётся декоративной. Проверка `--smoke`
теперь включает бег в ближайший ствол, столкновение машины и отъезд
задним ходом. NPC и трафик этот коллайдер пока не используют.

### Звук и стволы: результат следующего прохода

185 тестов и расширенный `--smoke` прошли. При запуске звук off, независимо
от предыдущего состояния тумблера в памяти старого запуска. Проверка
состояния аудиобэкенда:

```sh
fvm dart --packages=.dart_tool/package_config.json tools/qa/inspect_game.dart <vm-service-url> '"muted=$muted ready=$_ready master=${_engine.masterVolume}"' --audio
```

В готовой сборке начальные значения: muted=true, ready=true, master=0.0.

## Импорт стартового седана

Источник/лицензия и хеш исходника — в assets/models/CREDITS.md.
Повторная подготовка после скачивания исходника:

```sh
node tools/assets/prepare_classic_sedan.mjs /tmp/1980s-sedan.glb assets/models/vehicles/sedan_80.glb
```

Новый asset требует пересборки приложения. `hook/build.dart` теперь следит
и за вложенными каталогами assets, чтобы добавленные модели попадали в
flutter_scene_generated. Эти generated-файлы не коммитятся.

Проверять: четыре колеса стоят на земле и крутятся вокруг своих центров,
рулят только передние, фары смотрят вперёд (+Z игры), ночное свечение
не распадается на отдельные треугольники. После повреждений у кузова
должны оставаться текстуры ручек, молдингов и поверхности. Стёкла имеют
прозрачность, салон виден. Перекраска нового атласа пока не реализована:
у стартового седана фиксированный голубой цвет.

Результат этого этапа: 188 тестов и расширенный smoke на iPhone 18 Pro Max
прошли. В запущенной сцене подтверждены импорт sedan_80, четыре узла
колёс и muted=true. Осмотрены дневные/ночные фары и повреждённый кузов;
проверено сохранение текстур в damaged/wrecked. Повреждения для визуальной
проверки задавались только в памяти, затем сброшены перезапуском.


## Новый герой — 18.11.2026

Источник CC0 и SHA-256 указаны в assets/models/CREDITS.md. Подготовка:

```sh
node tools/assets/prepare_player.mjs /tmp/camper-animated.glb assets/models/characters/male_camper.glb
```

Входной файл скачивается по ссылке `download/zpepqtthci?combined=1`:
нужны именно родные Walk/Run. После изменения GLB нужна пересборка.
Проверять рост, опору стоп, отсутствие растянутых суставов, ходьбу на
малом отклонении стика, бег, прицеливание, лежащую позу и скрытие героя
при посадке в машину. Старые анимации NPC не должны попадать на новый
скелет; это проверяется контрактом roster и GLB.

На iPhone 18 Pro Max (iOS 27.0) осмотрены idle спереди, прицеливание и
лежащая поза. Расширенный smoke проверяет также активные Walk/Run и
скрытие водителя. Скрипт теперь ждёт завершения загрузки сцены до чтения
позиций: доступность VM Service ещё не означает готовность Game.

Результат: 192 теста и полный smoke прошли; звук muted=true. Анализатор
без ошибок/предупреждений, остаются 3 прежних info.

## Исправление геометрии, замеров и вождения

См. [FOUNDATION.md](FOUNDATION.md). 212 тестов; runtime smoke включает
площадку (900,900) для проверки шин/крена/ручника. Служебные маяки удалены,
высоты проверяются в исходных и детальных GLB. Старые цифры «FPS» по
обратному totalSpan НЕ являются частотой кадров; инструмент исправлен.
--frames выводит 5 окон каденса/p95/UI/raster; --profile пишет CPU samples.


Audio startup теперь muted=true, nativeReady=false, clips=0: бэкенд
создаётся при первом включении. Старый probe с _engine.masterVolume
нельзя вызывать до этого включения (поле late). Ленивая загрузка проверена
без звука: переключение on/off в одном событии, затем ready=true,
clips=16, master=0. После теста аудио нужен полный перезапуск процесса.

### Диагностика очереди подгрузки

`--stream-stats /tmp/stream.json` выгружает ограниченный журнал этапов
подгрузки. Async-замеры включают ожидание кадров и ресурсов; для оценки
непрерывной работы отдельно смотреть facade-commit, attach, vegetation.
`--drive /tmp/drive.json` фиксирует фактическую частоту кадров на маршруте;
`completed` должно быть true. Выход игрока из машины прерывает замер с
ошибкой. Не запускать тяжёлые тесты одновременно с измерением FPS.

### Благоустройство

```sh
node tools/assets/check_city_streets.mjs
fvm dart --packages=.dart_tool/package_config.json tools/qa/inspect_game.dart <vm-service-url> --city-smoke /tmp/city
```

Новый сценарий проверяет ночные/дневные фонари, близость лавочки,
завершение и отмену передышки; пишет `/tmp/city-night.png` и
`/tmp/city-day.png`. Запускать пешком, без ручного ввода в процессе.
Автомобильный smoke выбирает текущую машину: фоновые машины исключены
из кандидатов угона только на время синхронного нажатия кнопки посадки,
затем немедленно возвращены. Их движение и столкновения остаются.
Это проверка транспорта игрока, а не проверка угона случайной машины.

### Ограды и оборудование площадок

```sh
node tools/assets/check_city_layout.mjs
fvm dart --packages=.dart_tool/package_config.json tools/qa/inspect_game.dart <vm-service-url> --areas-smoke /tmp/areas
```

Сценарий бежит в ограду, проходит через вход, проверяет подгрузку трёх
площадок, наличие спортивного/скейт-покрытия и отсутствие рельефа над ним.
Сохраняет снимки трёх мест. Затем проверяет подъём пешехода на скейт-заезд.
Не запускать одновременно с другим runtime-сценарием или ручным вводом.
Стартовать пешком. Положение, камера и часы восстанавливаются в finally.
Отдельные тесты покрытия включают immutable byte-view из AssetBundle:
навигатор получает изменяемую копию данных, исходный asset не изменяется.

### macOS desktop

`fvm flutter run -d macos --enable-flutter-gpu` запускает нативное окно.
`--desktop-smoke` проверяет паузу и продолжение, а `--smoke` — общий
игровой сценарий на том же VM URL. Для этих сценариев симулятор не нужен.
Клавиатура и мышь проверяются в test/ui/desktop_controls_test.dart,
включая ПКМ без выстрела, независимые ЛКМ/F, сброс ввода при потере фокуса,
игнорирование действий на паузе и физический WASD при русской раскладке.
Не выполнять Flutter-сборки параллельно разными SDK: hook.dill в
.dart_tool/hooks_runner может остаться от несовместимого Dart SDK. При
`Invalid SDK hash` пересоздавать только кэш указанного build-hook/target,
а не исходные ассеты. SDK IDE закреплён в .vscode/settings.json через FVM.
