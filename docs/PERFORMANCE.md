# Производительность и повторяемые замеры

Цель: 60 игровых кадров в секунду, включая езду и смену чанков. Считать
цель достигнутой по одному среднему FPS нельзя: нужны интервалы кадров,
p95 и повторные проезды днём/ночью. Debug-сборка с JIT не является
контрольным замером производительности.

## Запуск

Основная конфигурация IDE «Crime Oren · macOS» теперь использует profile.
Для точек останова оставлена отдельная «Crime Oren · macOS · debug».

```
fvm flutter run --profile -d macos --enable-flutter-gpu
fvm flutter run --profile -d macos --enable-flutter-gpu --dart-define=PERF_BENCHMARK=true
```

Автотест последовательно сравнивает нативное разрешение, штатный бюджет
пикселей днём и ночью, затем старый перебор коллизий. Маршрут следует
центральной линии Илекской с поправкой на северную полосу. Розыск и
смерть исключены только из этого сценария, чтобы арест не подменял
замер езды стоянкой у спавна. Трафик и геометрические столкновения остаются.
Окно должно оставаться видимым; сворачивание сбрасывает замер. Результаты
пишутся в строки `PERF` stdout. Для CPU-профиля отдельной фазы:

```
fvm dart run tools/qa/profile_cpu.dart <VM-service-URL> 12 /tmp/crime-cpu.json
```

Не проводить параллельно сборки, тесты и измерения: их нагрузка искажает
замер. Сначала прогреть импорт и шейдеры; первые три секунды каждой фазы
автотест исключает. UI/raster — время Flutter-кадров, а scene FPS/p95 —
частота вызовов отрисовки 3D-сцены. Показатель не является прямым аппаратным
счётчиком показанных GPU кадров.

## Изменения

* Для статических чанков строится BVH по исходным треугольникам. Снимок
  CPU-буферов/матриц берётся один раз, преобразование и построение дерева
  выполняются в рабочем isolate. В сцену чанк попадает уже с индексом.
  Камера, персонаж, машина и пули используют его; подвижные машины
  сохраняют обычную проверку мешей. Индекс удаляется вместе с чанком.
* Небольшой desktop-уровень (сейчас 43 чанка, предел предварительной
  загрузки 64) прогревает общие ресурсные шаблоны на экране загрузки.
  В сцене по-прежнему только ближайшие чанки; дальние экземпляры не
  хранятся и не рисуются. Это переносит холодное чтение/создание GPU-ресурсов
  из езды в загрузку уровня, ценой более раннего удержания ресурсов в RAM.
  Для будущей большой карты потребуется потоковый импорт с бюджетом работ,
  а не увеличение этого предела.
* Дневные/ночные пайплайны и невидимые меши загруженной зоны прогреваются
  до входа в игру через `Scene.warmUp(includeOffscreen: true)`.
* `GameView` владеет часами симуляции и выбирает 60 Hz слоты. Просроченные
  кадры не воспроизводятся пачкой. `RepaintBoundary` отделяет 3D от HUD.
  Сторонняя перерисовка не запускает неявный шаг симуляции по настенным
  часам, в том числе на паузе.
* Desktop-рендер имеет бюджет 2 304 000 пикселей днём и плавно переходит
  к 1 800 000 ночью. Например, окно 1280×800 с Retina DPR 2 получает 3D
  1920×1200 днём, HUD остаётся нативным. Пресеты низкого разрешения не
  уменьшаются дважды. Модели, тени, растительность и дальность сохранены.
* Проверка наезда на пешехода явно проверяет
  наличие машины перед вычислением расстояния (исправляет найденное
  падение AOT-сборки).

## Контроль корректности

`test/world/static_collision_index_test.dart` проверяет ближайшую
двустороннюю поверхность, параллельные лучи и пространственные разбиения.
Автотест дополнительно сопоставляет новый и исходный raycast на загруженных
чанках. Тесты `frame_pacer_test.dart` проверяют 60/90/120/144 Hz, паузу
и фазовый шум ProMotion. Общий runtime smoke проверяет стены, деревья,
камеру, подвеску, поворот кузова и ручник.

CPU-данные стартового расследования: 5005 samples; `_intersectTriangles`
занимал 1866 self samples, обход raycast — 4081 inclusive samples. В первом
сравнении до исправления тестового маршрута старая проверка дала около
25–30 FPS; BVH с бюджетом пикселей — 60 FPS днём, p95 16.667 мс. Эти
ранние проезды включали остановки у препятствий; окончательные движущиеся
маршруты нужно оценивать отдельно.


## Контрольный прогон 19.11.2026

[Данные четырёх проездов на M1 Pro](performance/m1-pro-2026-11-19.json):
profile/AOT, Metal, штатный desktop-бюджет пикселей, прогрев 43 шаблонов.
Из каждого 15-секундного проезда исключены первые три секунды. Отдельно
учтены 674–719 интервалов движения на скорости больше 2 м/с в каждой фазе.

| Сценарий | FPS в движении | p95, мс | Максимум за фазу, мс |
|---|---:|---:|---:|
| День | 60.00 | 16.667 | 16.671 |
| Ночь | 60.00 | 16.667 | 16.668 |
| День, повтор | 60.00 | 16.667 | 16.670 |
| Ночь, повтор | 59.87 | 16.667 | 25.000 |

Конечные скорости 74.8–79.4 км/ч, смена стриминговых ячеек включена.
Кадров дольше 25.1 мс в этих четырёх фазах не было. Это результат данного
маршрута/конфигурации, а не гарантия для всех будущих сцен и устройств.
Резидентная память процесса в одной из точек измерения около 720 МБ
против около 415 МБ до предварительной загрузки; это не полный отчёт
обо всех GPU/системных аллокациях. Для парного повторения:

```
fvm flutter run --profile -d macos --enable-flutter-gpu --dart-define=PERF_BENCHMARK=true --dart-define=PERF_VARIANT=paired
```
