# Исходное ТЗ проекта

Это первое сообщение пользователя, с которого начался проект — полная
постановка задачи в изначальном виде, без изменений. Хранится здесь как
источник истины о видении проекта и полном списке систем, которые
планируются в конечном итоге (даже те, до которых мы ещё не дошли).

Текущий прогресс и то, что из этого списка уже сделано — в `PROGRESS.md`
и `README.md`. Технические решения, отклоняющиеся от буквального ТЗ (и
почему), — тоже в `PROGRESS.md`.

---

Ты — senior game developer, technical game designer и архитектор игровых систем. Твоя задача — помочь мне разработать полноценную open-world игру на Flutter 3.x/Dart, вдохновлённую современными 3D open-world играми в духе GTA, но с полностью оригинальными ассетами, кодом, персонажами, интерфейсом и игровым миром.

## 1. Главная цель

Создать постепенно масштабируемую игру с открытым миром.

Целевой формат:

* 3D open-world;
* вид от третьего лица;
* свободное исследование города;
* пешеходы;
* транспорт;
* полиция;
* оружие;
* физика;
* интерьеры;
* деньги и экономика;
* недвижимость;
* смена дня и ночи;
* погода;
* времена года;
* живой трафик;
* NPC с базовым AI;
* перестрелки;
* угон автомобилей;
* управление автомобилями;
* сохранение прогресса.

Если полноценная 3D-реализация на Flutter окажется технически нецелесообразной для конкретной системы, сначала предложи оптимизированный 3D-вариант. Если он объективно невозможен в рамках выбранного стека, только тогда предложи переход на 2D/2.5D, сохранив архитектуру игровых систем.

НЕ нужно пытаться сразу реализовать весь проект одним огромным файлом.

Проект должен строиться как настоящий масштабируемый игровой проект.

# 2. Город

Основной игровой мир — город Оренбург, Россия.

Первая игровая территория — Южный район Оренбурга.

Важно:

Город должен быть максимально похож на реальный Оренбург по:

* расположению улиц;
* форме кварталов;
* дорогам;
* перекрёсткам;
* зданиям;
* дворам;
* парковкам;
* магазинам;
* заправкам;
* общественным пространствам;
* основным достопримечательностям;
* рельефу;
* дорожной инфраструктуре.

Не придумывай произвольную карту, если можно использовать реальные географические данные.

При этом необходимо учитывать лицензии и авторские права. Не копируй коммерческие игровые карты, ассеты GTA или другие защищённые материалы.

Предложи pipeline получения геоданных и превращения их в игровой мир.

Например:

OpenStreetMap / открытые GIS-данные
→ обработка геометрии
→ генерация дорог
→ генерация кварталов
→ здания
→ дорожная разметка
→ навигационная сетка
→ игровые объекты.

Для первой версии не требуется моделировать каждый дом вручную.

Используй процедурную генерацию там, где это разумно.

# 3. Технологический стек

Основной стек:

* Flutter 3.x;
* Dart;
* 3D rendering engine / framework, совместимый с Flutter;
* физический движок, если он необходим;
* glTF/GLB для 3D-моделей;
* SQLite/Hive/Isar или другой подходящий локальный storage;
* JSON для конфигурации игровых объектов;
* asset bundles;
* навигационная система для NPC;
* spatial partitioning / streaming для большого мира.

Перед началом реализации:

1. Проанализируй современные возможности Flutter для 3D.
2. Выбери конкретный 3D-стек.
3. Объясни, почему выбран именно он.
4. Укажи ограничения.
5. Если выбранный стек не способен обеспечить необходимые возможности — предложи наиболее реалистичную альтернативу, но сохрани Flutter там, где это возможно.

Не делай вид, что Flutter автоматически является полноценным аналогом специализированного AAA game engine.

# 8. Угон автомобилей

Игрок может:

1. Подойти к автомобилю.
2. Попытаться открыть дверь.
3. Если автомобиль закрыт — выполнить механику взлома.
4. Если рядом владелец — возможна реакция NPC.
5. Игрок садится в машину.
6. Запускается двигатель.
7. Если угон замечен — NPC может вызвать полицию.

Не делай копию GTA-кода или ассетов.

Механика должна быть собственной.

# 28. Правила работы над кодом

Очень важно:

Не выдавай псевдокод там, где нужен рабочий Dart-код.

Каждый этап должен заканчиваться рабочим состоянием проекта.

Когда создаёшь файл:

1. Покажи полный путь.
2. Покажи полный код файла.
3. Объясни назначение.
4. Укажи зависимости.
5. Укажи команды запуска.

Не создавай код, который зависит от несуществующих классов.

Если файл требует другой файл — сначала создай необходимую зависимость.

Не используй устаревшие API.

Перед использованием стороннего пакета проверь его актуальность и совместимость с Flutter 3.x.

Если API конкретного пакета тебе неизвестен — не выдумывай его.
